# Kubernetes 教材编写规范（Textbook Style Guide）

> 本规范是教科书（textbook/ 目录，ch01~ch19）编写与修订的统一对照基准。**以已确认的第 2 章（ch02）为颗粒度样板**；如发现规范本身不合理，先更新本规范再继续。
>
> **版本基准**：本教材基于 **Kubernetes v1.36**（kubelet/kubeadm/kubectl 三件套同版本，containerd 2.2.x）。涉及版本差异的内容必须显式标注版本（如"v1.24+ 无长期 token"、"v1.27+ 引入"）。

---

## 1. 教材定位与边界（最重要）

| 原则 | 说明 |
|---|---|
| **教材讲 what / why** | 概念、原理、机制、设计决策、选型逻辑——"是什么、为什么" |
| **how 在实验手册** | 操作步骤、命令序列、yaml 细节属于 manual/ 实验手册；教材只作**验证点**或**概念示例**少量引用 |
| **教材 ≠ 实验手册说明书** | 可独立阅读；实验手册从属于教材（对教材知识点的演练） |
| **每章配套关系** | 章首引言标注对应实验手册章节；章末「实验演练指引」指向手册，不复制手册内容 |

**判断标准（自问）**：这一段如果删掉，读者是否还理解原理？如果删掉后只是"少了操作步骤"，说明它是 how，应该移到实验手册；如果删掉后"原理断了"，保留。

---

## 2. 每章统一骨架

```markdown
# 第 N 章 <中文章节名>

> 章首引言：配套实验手册章节 + 本章定位 + **版本基准声明**（"本课程基线 Kubernetes v1.36"，涉及版本差异处标注版本号）（1-3 行）

## 学习目标
（"学完本章，你应该能够"，5-10 条，每条可测量）

## N.1 <一级小节>
### N.1.1 <二级小节>
（主体按知识体系组织，可含：沙盒演练节、设计指南节、实验演练指引节）

## 本章小结
（要点回顾 + "衔接下一章" 一段）

## 思考题
（3-7 道引导性题目，可与实验手册观察点呼应）

> **CKA 考点标注**（blockquote 收尾）
```

> 可选章节：**沙盒演练**（如第 2 章 Killercoda）——当"集群还没建好但需要先动手"时插入，设计意图要写明。
>
> 可选小节：**「设计指南」**（厚度增强）——在现有章节中嵌入"规划与设计"内容，提升到"会设计与治理"层级：
> - 类型：容量规划（节点选型/CIDR 推演/etcd 基线）、多租户治理、HA/DR 架构、发布策略、命名规范、SRE 规范（SLO/复盘/运维日历）
> - 形式：决策树/清单/矩阵 + 决策逻辑（沿用 §3.3）；放在该主题小节之后，标题如 `### N.x 设计指南：xxx`

## 3. 内容规范

### 3.1 概念讲透，不留指针

- 所有"后面课程要设计的内容"**直接在本章介绍**（概念层面讲完整），**实操**扔到后续章节
- **禁止**"详见第 X 章/后面会介绍"这类推脱写法；允许"第 X 章展开实操/第 X 章深化"（区分：概念已讲完 vs 实操未做）
- **重要知识点反复提及不是问题**——前后章节呼应、多角度加深，鼓励

### 3.2 重要概念不用表格

- **重要概念（组件、机制、原理、哲学）禁止用表格带过**——用段落 + 列表 + 流程图（ASCII）展开讲
- 表格只允许两类：
  - **速查类**：命令速查、端口速查、字段速查
  - **对比决策类**：选型对比（如 CNI 插件对比、运行时对比）——表后必须跟"选型理由"段落
- 判断标准：**表格是否承载"讲解"**？承载讲解必须写成文字；纯对照/速查才用表

### 3.3 多选项必讲"为什么选它"

凡出现多个选项（安装方式/运行时/网络插件/存储方案/Service 类型…），必须：

1. 每个选项**讲清特点**（不列名字就完事）
2. 给出**适用场景**（各自用在什么时候）
3. 说明**本课程/本场景的选择理由**（2-4 条具体依据）
4. 用"**决策逻辑**"一句话收尾（可复用的选择思路）

### 3.4 重点机制必须展开

控制平面/数据平面/通信流程/命令式vs声明式这类**核心机制**，必须：

- 展开到"讲清内部怎么工作"（如 apiserver 的认证→授权→准入→持久化 五步）
- 用**流程图/文字图**（ASCII）呈现过程
- 给出**一个完整走查实例**（如"一次请求的旅程"、"3 副本自愈走查"）

### 3.5 命令的使用纪律

- 命令只作**验证点/概念示例**（如 `kubectl get nodes` 验证 Ready、`kubectl describe pod` 看事件）
- **禁止**大段命令块、操作序列、sed/配置文件细节——这些属于实验手册
- 命令出现的粒度参考第 2 章（少量、有讲解、有观察点）

### 3.6 环境变通（如国内镜像）

- 讲**问题本质**（为什么会有这个坑）与**解决思路**（有几类方案、各自原理）
- 具体脚本/步骤/实测数据指向实验手册附录
- 不喧宾夺主：通用流程为主，变通独立小节

### 3.7 颗粒度与篇幅

- **样板：第 2 章（ch02）**——概念密度高、每节有原理、流程图+走查完整
- 篇幅参考：400-900 行/章（视主题容量；宁深勿浅，不凑字数）
- 每章至少覆盖：核心概念详解、一个完整机制走查、选型决策、CKA 关联

---

### 3.8 术语对照（Glossary 规范）

- 首次出现的英文术语给出中文对照并保持一致（如 Pod（容器组）/Node（节点）/Namespace（命名空间）——**Pod/Node/Namespace 等核心名词按惯例不翻译**，保留英文）
- 建立**全书统一术语表**（textbook/GLOSSARY.md）：名词 → 中文对照 → 首次出现章节，防止多人协作术语割裂
- 同一术语全书用同一译法（如"调度器"不写"调度程序"）

### 3.9 图示规范

- 默认使用 **ASCII 代码块图**（渲染兼容性最好）
- 如目标平台支持 Mermaid.js（GitHub/GitLab 等），可选用 Mermaid 绘制复杂时序/架构图（` ```mermaid `），但**必须保证图后仍有文字讲解**
- 图后必须有文字讲解（每张图"读图指引"）

## 4. 格式规范

| 项目 | 规范 |
|---|---|
| 标题 | `# 第 N 章 <中文名>`；小节 `## N.1` / `### N.1.1`（中文冒号后接标题） |
| 文件名 | `chNN-english-name.md`（如 `ch02-kubernetes-overview-and-architecture.md`） |
| 版本声明 | 章首引言声明基线版本（v1.36）；版本差异处标注版本号（v1.24+/v1.27+/v1.25+） |
| 学习目标 | "学完本章，你应该能够：" + 编号列表（1. 2. 3.…），动词可测量（解释/对比/完成/说清） |
| 流程图 | ASCII 代码块（` ``` ` 内画流程/架构图），图后必须有文字讲解 |
| blockquote | 用于：关键认知、决策逻辑、教学提示、注意事项、CKA 标注 |
| ⭐ | 核心小节/核心概念标记（如 `## N.3 xxx ⭐`） |
| 表格 | 仅速查/对比决策类（§3.2），表后跟文字 |
| 术语 | 核心名词保留英文（Pod/Node/Namespace/Deployment/Service），次要术语首次出现给中文对照；见 GLOSSARY.md |
| 与手册呼应 | 章节编号引用用"第 N 章"；手册引用用"实验手册 NN 章" |
| CKA 标注 | 章末 blockquote：`> **CKA 考点标注**（对应域 X：名称 权重）：` + 必考命令/机制/排查列表 |

## 5. 每章写作流程

1. **先列骨架**：按 COURSE-OUTLINE.md 的章节设计列出小节标题
2. **填充概念**：每个小节先写"是什么→为什么→怎么工作"；重点机制画流程图
3. **补选型**：凡有多个选项的小节，补对比 + 场景 + 选择理由 + 决策逻辑
4. **补设计指南**：容量规划/多租户/HA-DR/发布策略/命名规范/SRE 等设计内容按需嵌入"设计指南"小节（§2 可选小节）
5. **写演练指引**：章末「实验演练指引」指向实验手册对应章节（含教学建议）
6. **自查清单**（下节）通过后交付

---

## 6. 质量检查清单（每章交付前自查）

- [ ] 无"详见第 X 章/后面会介绍"指针（"第 X 章展开实操"除外）
- [ ] 重要概念未用表格带过（组件/机制/原理均为文字+图）
- [ ] 无大段操作命令/步骤序列（属于实验手册）
- [ ] 所有多选项都有对比 + 场景 + 选择理由 + 决策逻辑
- [ ] 核心机制（控制面/数据面/通信等）有展开讲解 + 至少一个走查实例
- [ ] 学习目标可测量（不是"了解"而是"解释/对比/完成"）
- [ ] 章首标注配套实验手册章节 + 版本基准声明；章末有实验演练指引
- [ ] 有本章小结（含衔接下一章）、思考题、CKA 考点标注
- [ ] fence 全部闭合（``` 成对）
- [ ] 国内环境变通：只讲本质与思路，脚本在实验手册
- [ ] 术语与 GLOSSARY.md 一致
